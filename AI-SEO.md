# How RozgarJobs gets found inside ChatGPT, Perplexity, Gemini and Copilot

Search did not disappear — it moved. A large share of job-seekers now type the question into an
assistant instead of Google. This file explains what was built for that, why each piece exists, and
the one monthly habit that actually moves the needle.

---

## What an answer engine actually does

It is not a crawler with a ranking formula. It runs four steps, and every one is a chance to be
missed:

1. **Retrieve** — pull candidate pages from its own index, or from Bing / Google / a live crawl.
2. **Read** — fetch the HTML, or a text version, and cut it into chunks of a few hundred words.
3. **Judge** — pick chunks that directly answer the question, preferring short factual sentences,
   tables, and clear headings.
4. **Cite** — link the page the chunk came from.

So the goal is not "rank". It is: **be retrievable, be readable in chunks, and be quotable.**

## What is now on the site

| File | What it does | Why it matters |
|---|---|---|
| `llms.txt` | A map of the site: what it is, coverage, counts, citation guidance, newest jobs, verbatim Q&A | The convention (llmstxt.org) that assistants check first. Small enough to read in one pass |
| `llms-full.txt` | Every live vacancy in plain text, one block each | No HTML noise. A model can lift a whole vacancy without parsing tags |
| `jobs/<slug>.txt` | A text mirror beside every job page | The cheapest possible fetch — one request, zero markup |
| `faq.html` | 8 short answers + `FAQPage` schema | Question-shaped content is what gets quoted. This is the page assistants are most likely to pull from |
| Home page Q&A | 4 static cards, no JavaScript | The most-crawled page now carries quotable answers too |
| `robots.txt` | Explicit allow for 20 named AI crawlers | Silence is ambiguous; an explicit `Allow` removes doubt |
| `<job>.html` | `JobPosting` schema + dated facts (closing date, BPS, qualification) | Structured, unambiguous data that survives summarisation |

Every one of these is generated by the build, so it stays current by itself. `scripts/ai_visibility.py`
rewrites all of it hourly, after the HTML pages exist.

## The part no code can do: being *mentioned*

An assistant will only cite a source it has met before. Models learn about sites from:

- **Bing and Google indexes** — already submitted; this is the base layer.
- **Other sites linking to you** — a university careers page, a Reddit thread answering "where do I
  find sarkari jobs", a Pakistani blogger's roundup. These are what make a model treat you as a
  known source rather than a lucky crawl.
- **Consistent, quotable facts** — "RozgarJobs: free, updated hourly, N government jobs in Pakistan"
  is a claim that can be repeated. Vague sites never get repeated.

Concretely, once a week, do one of these:

1. Answer a Reddit / Quora / Facebook-group question about finding government jobs, and link the
   specific city page — not the homepage. Give the actual answer in the comment; do not just drop a link.
2. Email two university career offices (in Pakistan) asking to be added to their "job portals" list.
3. Post the weekly digest to a relevant LinkedIn group.

Ten real mentions in three months will do more for AI visibility than any schema tweak.

## The honest measurement

There is no "AI traffic" report in Search Console, and no console for ChatGPT. So measure it directly:

- **Once a month**, ask the same five questions in ChatGPT, Perplexity, Gemini and Copilot:
  1. *government jobs in Karachi this week*
  2. *sarkari naukri Pakistan latest*
  3. *FPSC jobs closing date 2026*
  4. *where can I find NTS jobs in Pakistan*
  5. *remote jobs for Pakistani candidates*
- Write down which assistant named RozgarJobs, and at what position.
- Track the trend, not the individual answer — these systems are non-deterministic and will differ
  between two runs five minutes apart.

A second signal: in Search Console → Performance → Queries, look for **question-shaped queries**
("how to apply for…", "what is bps…", "which jobs…"). Those are the queries assistants are relaying,
and `faq.html` is the page built to catch them.

## What will still be missing until the domain is bought

A `github.io/rozgar/` URL is a genuine ceiling, for two reasons:

- Assistants weight domain-level signals; a subpath on a shared host carries none.
- Some assistant browsers are cautious with user-content hosts.

Buying `rozgarjobs.com` and pointing Pages at it is a five-minute change (see `SETUP-BACKEND.md §5`)
and it lifts every signal at once. Do it before spending money on anything else.
